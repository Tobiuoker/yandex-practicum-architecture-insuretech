# Задание 5. Обоснование GraphQL-модели

## Почему такая модель

В исходном REST API есть три ресурса: клиент, его документы и родственники. Поэтому выбрана одна корневая сущность `Client` с вложенными полями `documents: [Document]` и `relatives: [Relative]`. Поля сущностей сохранены из Swagger без добавления новых.

## Как работает

Точка входа — `client(id: ID!): Client`. Потребитель сам указывает нужные поля, включая вложенные данные:

```graphql
query {
  client(id: "123") {
    name
    documents { type number }
    relatives { name relationType }
  }
}
```

Сервер возвращает только перечисленные поля. Один запрос заменяет обращения к `/clients/{id}`, `/clients/{id}/documents` и `/clients/{id}/relatives`.

## Чем удобно

- **Меньше запросов:** связанные данные получаются за одно обращение.
- **Меньше трафика:** не передаются ненужные поля большой карточки клиента.
- **Гибкость:** веб-приложение и `core-app` выбирают разные наборы данных без новых REST-эндпоинтов.

Предусмотрен только `Query`, поскольку исходный Swagger описывает лишь операции чтения (`GET`).
