# Задание 4. ОСАГО

| Решение | Зачем |
|---|---|
| **`osago-aggregator` + своя PostgreSQL** | Отдельная обработка заявок, статусов по страховым и надежная очередь задач. |
| **`core-app -> osago-aggregator`: REST** | Быстро принять заявку, не ожидая ответов страховых. Повторы защищены `Idempotency-Key`. |
| **Независимый polling страховых каждые 5–10 с + jitter** | Показывать предложения по мере готовности и распределять нагрузку. Общий дедлайн - **60 с**. |
| **Retry до 5 раз с exponential backoff, Timeout до 5 с, Circuit Breaker** | Переживать временные ошибки и не ждать недоступные API. Повторы только в пределах 60 с. |
| **Rate Limiter на каждую страховую** | Соблюдать лимиты партнеров; общий лимит между репликами через Redis. |
| **Transactional Outbox -> Kafka `osago.results`** | Не терять результаты при сбоях между записью в БД и публикацией события. |
| **Kafka -> `core-app` -> Redis Pub/Sub -> SSE -> Web** | Сразу показывать ответ каждой страховой нужному пользователю, независимо от реплики `core-app`. |
| **Несколько реплик сервисов** | Задачи распределяются через БД (`lease` / `SKIP LOCKED`), SSE-соединение обслуживает владеющая им реплика; результаты сохраняются для переподключения. |

**Итог:** оформление не блокируется ожиданием страховых; предложения поступают отдельно, по готовности, в пределах 60 секунд.
